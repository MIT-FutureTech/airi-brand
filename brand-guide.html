Usage

  • Primary (#A32035) — buttons, links, headings, accents, logo
  • Primary Light (#D07886) — hover tints, secondary highlights, tags
  • Primary Dark (#5E0E20) — hover states for primary buttons
  • Dark (#1A1A1A) — body text, headings on light backgrounds
  • Gray (#898A8D) — muted text, captions, secondary borders
  • Background (#FAFAFA) — page background
  • Do not introduce additional brand colors. Use opacity variations if needed.

PROPOSED Image and illustration style guide Issue #6

The brand spec has no guidance on imagery. Propose adding a visual philosophy and style rules:

  • Style: Abstract geometric and mathematical art — tessellated patterns, network graphs, Voronoi diagrams, topological surfaces.
  • Pattern mapping: Each AIRI tool gets a signature visual motif (Repository = lattice, Incidents = fractal branching, Governance = overlapping circles, Mitigations = hexagonal tessellation)
  • Rules: No text in images, no photorealism, no AI-generated faces. Photography only for headshots.
  • Colors: Use extended palette for variety. MIT red as accent, not dominant.

See image catalog with reproducible prompts

Key question: How prescriptive should the pattern-to-tool mapping be? Strict rules ensure consistency; loose guidance allows flexibility.
UNDER REVIEW Additional web component patterns Issue #7

Propose adding component patterns that emerged as necessary during the mockup:

  • Stats bar: Key numbers in primary with labels in gray. Content-relevant metrics, not vanity numbers.
  • Carousel: Horizontal scroll-snap with arrow controls. For blog posts, testimonials, data snapshots.
  • Logo display: Partner/media logos in greyscale, hover to full color. Group partners by sector.
  • Testimonials: Blockquote with open-quote accent, author + role.
  • Section rhythm: Alternating #FAFAFA / #FFFFFF backgrounds.
Key question: Do these belong in the brand spec or a separate design system doc? The current spec already includes buttons and cards, so precedent exists.
OUT OF SCOPE Findings documented elsewhere

These emerged from persona reviews but belong in a separate content/UX guidelines doc:

  • Tone of voice: Avoid jargon, be precise about org relationships, include data freshness dates. (Closed #8)
  • CTA strategy: Differentiate CTAs by audience — policymakers, researchers, industry. (Closed #9)
